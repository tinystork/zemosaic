# Testing

This file is the durable protocol for running ZeMosaic's test suite. It is the
fix for the historical "full-suite replay" habit: without it, every change was
validated by 3–4 full-suite replays (~1.5–2 h of machine time per mission).

## Test tiers

The suite is split into two tiers via a single `slow` marker registered in
`pyproject.toml` (`[tool.pytest.ini_options] markers`):

| Tier | Command | What it is |
|------|---------|------------|
| **Fast (loop gate)** | `pytest -m "not slow"` | Everything that does NOT need the local corpora (M16/quick, M106/lights, `zegrid_r*_fixtures`) and does NOT run a full M16/M106 pipeline. Runs in CI, ~1–3 min. |
| **Slow (gated)** | `pytest -m slow` | The heavy/gated end-to-end checks: full pipeline runs, real-cell parity, M16 measurement, memory-model calibration. These need the local corpora and are the human/release gate. |
| **Full** | `pytest` | Everything. Run ONCE at commit (see below). |

> `pytest-xdist` is **not** a required dependency. If it is already installed,
> use `pytest -m "not slow" -n auto` for the fast tier; otherwise the plain
> command above is fine. Do not add a new dependency just for this.

## Who runs what

- **Implementer** (per iteration): `pytest -m "not slow"` after every change;
  `pytest` **once** at commit (never per iteration).
- **Independent reviewer**: targeted tests + adversarial probes. **No full
  suite.** Reviewers pick the specific files/behaviours the change touched and
  run those, plus a few neighbouring/regression files.
- **Architect**: targeted tests per mission + the PR gate (see below).
- **Human / release gate** (the user's Windows runs): the full suite over the
  real corpora, incl. the `slow` tier.

## CI role

- `.github/workflows/test-tiers.yml` runs the **fast tier** (`pytest -m "not
  slow"`) on pull requests to `beta`, plus a **nightly** scheduled full
  non-gated run. The CI runner has **no local corpora**, so the gated (`slow`)
  tests skip there (they already skip when the fixture is absent) — CI is
  lightweight and never touches the corpora.
- `.github/workflows/no-tk-on-official-path.yml` is untouched (import guard).

## Gated corpora (where they live)

These live **outside git** on the human's machine; the `slow` tests skip cleanly
when they are absent:

- `/home/tristan/M16/quick` — M16 "iteration speed" dataset (R11/R12 gauge + cache).
- `/home/tristan/M106/lights` — M106 lights (R1/R2/R3/R4/R7/R14/R15 + R6 parity).
- `/home/tristan/zegrid_r2_fixtures` (and `/tmp/zegrid_r1_fixtures`) — prepared RGB fixtures.
- `/home/tristan/zegrid_r10_sip_fixture`, `/home/tristan/caldwell11/...` — SIP recovery fixtures.
- Persisted outputs: `/home/tristan/zegrid_r3_m106_outputs`, `zegrid_r4_m106_tight`, etc.

The **routine corpus** (small, deterministic, on disk) is generated by
`tools/zegrid_routine/make_routine_corpus.py` and used by
`tests/test_zegrid_routine_e2e.py` — the everyday end-to-end pipeline smoke that
needs no corpora and runs in the fast tier/CI.

## Shared session fixtures

`tests/conftest.py` registers two session-scoped fixtures that build/load the
reusable gated corpora ONCE per session, so the gated tests no longer re-read
the manifest + rebuild the canvas per file:

- `m106_corpus` → `(frames, rejected, canvas)` for M106.
- `m16_corpus` → `(descs, canvas)` for M16.

## Commands cheat-sheet

```bash
# Fast tier (loop gate; CI PR gate)
python -m pytest -m "not slow" -q

# Slow/gated tier (human + release)
python -m pytest -m "slow" -q

# Full suite (ONCE at commit)
python -m pytest -q
```
